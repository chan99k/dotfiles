# Skill Usage Audit

## Overview

스킬 목록이 늘면 안 쓰는 스킬이 컨텍스트 예산을 먹는다. 이 스킬은 **호출 기록을 근거로** 어떤 스킬을 아카이브·수정·유지할지 판정한다.

핵심 원칙: **호출 0회는 "쓸모없다"가 아니라 "왜 안 쓰였는지 조사하라"는 신호다.** 안 쓰인 이유가 스킬 결함(설명이 안 맞음)인지 수요 소멸인지에 따라 처방이 정반대다.

## 데이터 소스

`~/.claude/telemetry/` 는 **쓰지 않는다.** 그 폴더의 `tengu_skill_loaded` 는 세션 시작 시 전 스킬에 대해 찍히는 카탈로그 등록 이벤트라 사용량 신호가 없고, `1p_failed_events.*` 는 전송 실패분만 남은 편향 표본이다.

실제 호출은 세션 트랜스크립트(`~/.claude/projects/**/*.jsonl`)의 `Skill` tool_use 에만 있다. `audit.py` 가 이걸 읽는다.

## 절차

```bash
python3 ~/.claude/skills/skill-usage-audit/audit.py          # 전체 표
python3 .../audit.py --days 90                               # 최근 90일 창
python3 .../audit.py --json                                  # 기계 판독용
```

1. 감사 실행. 표 하단의 **아카이브 금지** 줄을 먼저 읽는다.
2. 후보 = 호출 0회 중 금지 목록에 없는 것.
3. 후보마다 아래 판정 레코드를 채운다.
4. `판정: archive` 인 것만 실행한다:

```bash
python3 .../audit.py --archive <이름> --reason "<근거>"
```

스크립트가 플러그인 소유·`~/.agents` 공유물·살아있는 참조자·호출 이력을 거부한다. 거부당하면 그 스킬은 아카이브 대상이 아니다. `--force` 로 뚫지 말고 판정을 다시 하라.

## 판정 레코드 (모든 슬롯 필수)

```
스킬:
무엇을 하는가:    ← SKILL.md 를 열어서 한 줄. 감사 표만 보고는 채울 수 없다.
전제 조건:        ← 그 SKILL.md 가 요구하는 도구/설정파일/외부 시스템. 없으면 "없음"
전제 충족 여부:   충족 | 미충족(무엇이 없는지)  ← 파일시스템에서 실제로 확인한 결과
그 작업을 했는가: 예(스킬이 안 불림) | 아니오
대체 스킬:        같은 일을 하는 다른 스킬 이름, 없으면 없음
판정:            ← 아래 명령이 출력한 문자열을 그대로 옮긴다
근거:
```

`무엇을 하는가` 에 "추정", "불명", "~로 보임" 이 들어가면 그 레코드는 미완성이다. 파일을 열어라.

## 판정은 계산한다

판정을 직접 고르지 마라. 관측한 사실을 넣으면 스크립트가 판정을 준다.

```bash
python3 .../audit.py --verdict <이름> --premise met|unmet [--did-work] [--superseded-by <스킬>]
```

- `--premise unmet` — 전제 조건이 환경에 없다
- `--did-work` — 그 작업을 실제로 했는데 이 스킬이 안 불렸다
- `--superseded-by` — 같은 일을 하는 다른 스킬. 그쪽이 0회면 대체로 인정되지 않는다

호출 이력, 살아있는 참조자, 소유처(플러그인·`~/.agents`)는 스크립트가 이미 알고 있으므로 넣지 않아도 된다.

출력이 곧 판정이다. 다르게 적고 싶어지면 관측을 다시 하라 — 판정을 바꾸는 게 아니라 입력을 바로잡는 것이다.

세션 수는 호출 수와 별개 신호다. 27호출/2세션은 이틀짜리 작업이었고 58호출/51세션은 상시 도구다. keep 근거에 이 차이를 적는다.

## Red Flags — 멈추고 다시 하라

- 후보 목록을 받고 SKILL.md 를 한 개도 열지 않았다
- 근거에 "추정", "정체 불명", "~ 용도로 보이나"
- "참조하는 쪽도 호출 0회니까 무효" — 참조 칸의 괄호 숫자를 다시 봐라
- 참조 방향을 "A가 나를 참조" 로 읽었는지 확인 없이 진행
- 한 번에 10개 넘게 archive 판정 — 조사 없이 수치로만 자른 것이다
- `전제 충족 여부` 를 파일시스템 확인 없이 적었다
- `--verdict` 를 돌리지 않고 판정을 직접 골랐다
- `--verdict` 출력과 다른 판정을 레코드에 적었다
- `--force` 를 쓰고 싶어짐

## Common Mistakes

| 실수 | 실제 |
|---|---|
| 0회 = 무용 | 트리거 문구가 안 맞아서 안 불린 것일 수 있다. 그건 revise 대상이다 |
| 참조 클러스터 통째 제거 | 서로 참조하는 묶음은 한 덩어리로 살거나 죽는다. 하나씩 판정하지 말고 묶음의 도입 여부를 물어라 |
| 플러그인 스킬 아카이브 | 마켓플레이스 갱신 때 되살아난다. 플러그인 비활성화로 처리 |
| 아카이브 후 재감사에서 "역시 0회" | 아카이브된 스킬은 당연히 0회다. `_archive/ARCHIVED.json` 대장으로 제외된다 |

## 복구

아카이브는 파일 이동 + 심링크 제거이고 dotfiles 는 git 추적 중이라 되돌릴 수 있다. `--archive` 출력 마지막 줄에 복구 명령이 그대로 찍힌다.
