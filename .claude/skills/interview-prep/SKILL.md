# 면접 준비

## Overview

기술이사(면접관) 관점의 면접 기준. 전제 셋:
**합격은 30분 내에 결정난다. 면접관은 이력서를 완벽히 보고 오지 않는다.
그리고 면접관은 탈락시킬 이유를 찾는다.**

그래서 면접 준비의 본질은 "많이 아는 것"이 아니라 **앞 30분 안에, 상대가 모르는 내 맥락을,
탈락 사유를 만들지 않는 방식으로 전달하는 것**이다.

## When to Use

- 면접 일정이 잡혀 준비를 시작할 때
- 자기소개·예상 질문·답변을 다듬을 때
- 기술 면접 / 시스템 디자인 대비
- 면접 직후 복기(면접 일지)

## 답변의 형태 (이 모양을 지킨다)

한 답변은 다음 순서로 만든다.

1. **결론 한 문장** — 질문에 대한 직접적인 답
2. **근거** — 내가 한 것, 측정한 것, 관찰한 것
3. **판단** — 왜 그 선택을 했고 무엇을 포기했는가
4. (필요 시) **한계** — 지금이라면 무엇을 다르게 할까

짧으면 성의가 없고, 길면 집중을 잃는다. 두루뭉술하면 검증이 안 되고, 근거가 없으면 신뢰가 없다.
**모르면 모른다고 말하되, 거기서 끝내지 말고 추론을 이어 붙인다** — 면접관은 모르는 것을
추론할 수 있는지를 본다.

## 하지 말아야 할 것

| 하지 말 것 | 왜 |
|---|---|
| 모든 걸 외워서 말한다 | 대본은 들린다. 꼬리 질문에서 무너진다 |
| 회사마다 똑같이 준비한다 | 지원 동기가 비게 된다 |
| 자기소개를 길게 한다 | 첫인상이 여기서 결정된다. 짧고 방향을 담아 |
| 질문 의도를 파악하지 않고 답한다 | 다른 질문에 답하게 된다 |
| 확대 해석하거나 삼천포로 빠진다 | 시간이 사라지고 통제력이 없어 보인다 |
| 억지로 경험을 끼워 맞춘다 | 이력과 모순이 생긴다 |
| 아는 척한다 / 완벽한 것만 말한다 | 반드시 들킨다 |
| 실패를 숨긴다 | 실패를 다룬 방식이 평가 대상이다 |
| 도메인을 장황하게 설명한다 | 면접관은 내 회사 도메인을 모르지만, 듣고 싶은 건 내 판단이다 |
| **기밀 사항을 말한다** | 즉시 탈락 사유. 미공개 수치·장애 이력·사내 코드는 말하지 않는다 |
| 면접관 반응에 흔들린다 | 무표정과 침묵은 평가가 아니다 |
| 이상한 역질문을 한다 | 마지막 질문도 평가된다 |

## 준비 체크리스트

- [ ] **내 이력서를 100% 이해한다** — 면접관보다 내가 더 잘 알아야 한다. 설명 못 할 항목은 미리 지운다
- [ ] **이력서에 미끼를 넣는다** — 받고 싶은 질문이 나오도록 설계한다
- [ ] **채용 공고를 분석한다** — 공고의 어휘로 답변을 만든다
- [ ] **지원 동기를 명확히 한다** — 회사를 모르는 지원자에게 면접관은 부정적이다
- [ ] **도메인을 이해한다** — 그 회사가 무슨 돈을 어떻게 버는지
- [ ] **자기소개로 면접의 방향을 만든다** — 이후 질문을 내가 원하는 쪽으로 유도
- [ ] **스토리를 요약해 설명하는 연습** — 프로젝트당 30초 / 3분 두 버전
- [ ] **내 장단점을 정확히 안다**
- [ ] **GitHub·블로그 질문 대비** — 적어 냈으면 반드시 물어본다
- [ ] **트레이드오프 질문 대비** — 왜 A이고 왜 B가 아닌가
- [ ] **시스템이 성장했을 때** — 트래픽이 10배면 어디가 먼저 터지나
- [ ] **역질문 준비**

## 태도

- 긴장되면 긴장된다고 말한다
- **생각하고 답한다.** 침묵 뒤에 나오는 답변을 면접관은 더 신뢰한다
- 사람과의 대화라는 걸 잊지 않는다. 논리적으로 접근해 답한다
- **꼬리 질문의 함정** — 계속 파고드는 건 틀렸다는 신호가 아니라 경계를 확인하는 것이다.
  모르는 지점에 도달하면 인정하고, 어떻게 알아낼지를 말한다
- 압박 질문과 침묵에는 이유가 있다. 반응을 평가로 오독하지 않는다

## 면접관의 시선 (알고 들어간다)

- 면접관은 **회사를 대표**하고, **시간이 부족**하며, **이력서를 검토한 사람이 아닐 수 있다**
- 질문은 미리 준비해 오기도 하고 즉석에서 만들기도 한다. **의미 없는 질문은 없다**
- 모든 답변에 100% 집중하지 못한다 → 핵심을 앞에 둔다
- 논리력을 검증한다. 모르는 것도 추론 가능한지 본다
- 면접관도 모든 걸 알지 못한다. 기술뿐 아니라 **사람도 같이 본다**
- 연차별로 접근법이 다르다. 첫 면접과 마지막 면접의 성격이 다르다
- 면접이 길어지면 문제가 있다는 신호일 수 있다
- **최종 합격 기준은 "같이 일할 수 있는가"**이고, 면접관은 끝에 **한 줄 요약**을 만든다
  → 내 한 줄 요약이 무엇이 되길 원하는지 정하고 들어간다

## 면접 후

- **녹음한다** (상대 동의·법적 허용 범위 확인)
- **면접 일지를 쓴다** — 받은 질문, 막힌 지점, 다음에 바꿀 것.
  같은 질문은 회사를 바꿔 가며 반복된다

## 부록

- **면접에도 운이 있다.** 한 번의 탈락을 실력 판정으로 받지 않는다. 머저리 면접관도 있다
- **신입의 기술 면접 준비** — 넓게 얕게가 아니라, 내가 만든 것 안에서 깊게. 내 프로젝트가 곧 출제 범위
- **시스템 디자인 질문** — 요구사항 확인 → 제약 명시 → 단순한 설계 → 병목 지목 → 확장안 순서로
- **레거시 경험 어필** — 무엇을 바꿨고 **무엇을 일부러 안 바꿨는지**를 말한다
- **AI 경험 어필** — AI에 맡긴 범위와 사람이 판단한 범위의 구분, 그리고 검증 방법
