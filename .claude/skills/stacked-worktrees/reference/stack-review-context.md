# Stack Review Context

리뷰 진입점(`apply-review`, `preflight-review`, 클라우드 리뷰)이 스택된 PR을 다룰 때 공유하는 절차.

**핵심 원칙:** 상위 PR의 diff는 참고 자료가 아니라 **대조 대상**이다. 읽기만 하고 하위 PR 원문과
맞춰보지 않으면, 컴파일조차 되지 않는 계약 위반이 두 리뷰 모두를 통과한다.

## 1. 스택 감지

```bash
gh pr list --json number,headRefName,baseRefName,isDraft,title,url
```

다음 중 하나면 스택이다.

- 대상 PR의 `baseRefName`이 default branch가 아니다 (아래에 PR이 있다)
- 다른 PR의 `baseRefName`이 대상 PR의 `headRefName`이다 (위에 PR이 있다)

둘 다 아니면 스택이 아니다. 이 문서를 덮고 원래 리뷰 절차로 돌아간다.

체인은 `baseRefName` 링크로만 복원한다. **PR 번호순은 의존순이 아니다** — 번호로 순서를
추측하지 않는다.

## 2. 수집

```bash
gh pr diff <n> --name-only     # 스택의 모든 PR
gh pr diff <n>                 # 대상 PR과 파일이 겹치는 PR만 전문
```

대상 PR이 정의한 심볼을 상위 PR이 쓰는지 보려면, 겹치는 파일이 없어도 상위 PR 전문이 필요하다.

## 3. 교차 PR 계약 검증 (REQUIRED)

**이 절은 건너뛸 수 없다.** 단일 PR 리뷰가 원리상 볼 수 없는 유일한 부분이고,
베이스라인 테스트에서 5회 중 5회 누락된 지점이다.

리뷰 대상이 스택의 어느 위치든, 아래 네 슬롯을 모두 채운다. **슬롯을 지우지 않는다.**

- 확인했고 해당 사항이 없으면 → `없음`
- 확인 자체를 못 했으면 → `미확인: <이유>` 한 줄

`없음`과 `미확인`을 섞지 않는다. 명령을 못 돌려서 모르는 것을 `없음`으로 적으면, 검증하지
않은 것이 검증 결과로 둔갑한다.

**계약 위반은 대상 PR이 아니라 상위 PR을 깨뜨린다.** 대상 PR은 혼자서는 컴파일된다 —
깨지는 쪽은 그 심볼을 쓰는 위쪽이다. 심각도는 낮추지 말되(스택은 어차피 통째로 못 나간다),
"이 PR 착지 불가"가 아니라 "#178 컴파일 불가"로 정확히 쓴다.

### 슬롯 1: 심볼 대조

상위 PR이 하위 PR의 타입을 건드리는 줄을 전부 뽑아, 하위 PR 원문에서 하나씩 확인한다.
목록 대조지 판단이 아니다.

| 확인할 것 | 놓치면 |
|---|---|
| 호출한 메서드가 **존재하는가** | 컴파일 실패 |
| 접근한 프로퍼티의 **가시성** (`private`/`internal`) | 컴파일 실패 |
| 시그니처·파라미터 수·타입이 맞는가 | 컴파일 실패 |
| nullability가 맞는가 | 런타임 실패 |

`policy.hasRules()`를 서술하려면 하위 PR에서 `hasRules`가 **선언된 줄**을 앵커로 쓴다.
못 찾았으면 그것이 결함이다. "있겠거니" 하고 넘어가지 않는다.

### 슬롯 2: rework

상위 PR이 하위 PR이 쓴 코드를 되돌리거나 다시 쓰는가. 있으면 그것은 코드 문제가 아니라
**스택 분할이 잘못됐다는 신호**다. 어느 PR이 어느 줄을 되돌리는지 앵커로 적는다.

### 슬롯 3: restack 상태

```bash
git -C <상위 worktree> merge-base --is-ancestor origin/<하위 브랜치> HEAD && echo OK || echo STALE
```

`STALE`이면 상위 브랜치가 하위의 옛 tip 위에 있다. 리뷰 중인 코드가 실제로 머지될 코드와
다르다는 뜻이므로, 리뷰를 계속하기 전에 보고한다. 복구는 `stacked-worktrees` Step 4.5.

### 슬롯 4: 경계 오류

같은 파일을 스택의 여러 PR이 반복 수정하는가. 1단계 수집의 `--name-only` 목록을 대조해
중복 경로를 그대로 옮겨 적는다. 경로가 없으면 `없음`. 중복이 있으면 그것이 정당한지 한 줄로
판단한다.

## 4. 후행 해소 표기

후행 PR에서 해소되는 지적은 **지우지 않는다.** 남기고 앵커와 함께 표기한다.

```
[필수→제안] DiscountPolicy.kt:4
  미사용 프로퍼티 `auditContext`
  → #178 ApplyDiscountUseCase.kt:5 에서 사용. 하향.

[필수] DiscountPolicy.kt:7
  rules 가 비면 NPE
  → #178 에서 방어되나, #177 착지 시점 main 이 깨짐. 유지.
```

판정 기준은 한 줄이다.

> **이 PR이 착지하는 시점의 main에서, 이 지적이 실제 장애를 만드는가?**

스택은 bottom-first로 착지한다(`stacked-worktrees` Step 5). #177이 머지되는 순간의 main에는
#178이 없다. 상위 PR의 방어 코드는 그 시점에 존재하지 않는다.

| | 유형 |
|---|---|
| 하향 허용 | 죽은 코드, 미사용 심볼·파라미터, 구현체 1개뿐인 추상화, 미사용 확장 지점 |
| 하향 금지 | 버그·NPE·보안·마이그레이션 비호환·성능 회귀, 테스트 누락, 계약 위반 |

**앵커 없는 하향은 하지 않는다.** 후행 해소를 주장하려면 후행 PR의 `파일:줄`을 댄다.
못 대면 하향하지 않고 그대로 둔다.

## 5. 스택 구조에 대한 제안 금지

리뷰는 코드를 판정하는 자리지 스택을 재편하는 자리가 아니다.

- "일정이 급하니 하나의 PR로 합치자"
- "상위 PR을 default branch에 직접 붙이자"

`stacked-worktrees` Prohibitions가 금지하는 항목이다. 스택이 정말 잘못 나뉘었다고 판단되면
슬롯 2에 근거를 적고 사람에게 보고한다 — 리뷰 코멘트로 해체를 제안하지 않는다.

## Red Flags — 멈추고 원문을 연다

- 교차 PR 계약 검증의 슬롯이 비어 있거나 지워져 있다
- 확인하지 못한 슬롯에 `미확인:` 대신 `없음`이라고 적었다
- 계약 위반을 "대상 PR 착지 불가"로 서술했다 (깨지는 것은 상위 PR이다)
- 상위 PR이 쓰는 심볼을 언급하면서 그것이 **선언된 줄**을 열지 않았다
- 후행 해소를 앵커 없이 주장했다
- 버그·보안·테스트 누락을 후행 해소로 하향했다
- 스택 순서를 PR 번호로 추측했다
- 리뷰 코멘트에 스택 해체·통합 제안이 들어 있다

## Quick Reference

| 상황 | 행동 |
|---|---|
| 스택 여부 판정 | `gh pr list --json number,headRefName,baseRefName` |
| 체인 순서 | `baseRefName` 링크. 번호순 아님 |
| 상위 PR diff | 참고 자료가 아니라 대조 대상 |
| 상위가 하위 심볼 사용 | 하위 원문에서 존재·가시성·시그니처 확인 |
| 슬롯 해당 없음 | `없음`. 확인 못 했으면 `미확인: <이유>`. 지우지 않는다 |
| 계약 위반 서술 | "#178 컴파일 불가". "이 PR 착지 불가"가 아니다 |
| 후행 해소 | 지우지 말고 앵커와 함께 표기 |
| 하향 판단 | "착지 시점 main이 깨지는가" |
| 상위 브랜치가 STALE | 리뷰 중단하고 보고 (Step 4.5) |
| 스택이 잘못 나뉘어 보임 | 슬롯 2에 근거 + 사람에게 보고 |
