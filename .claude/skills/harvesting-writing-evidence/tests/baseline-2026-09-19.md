# RED baseline, 2026-09-19

Scenario: general-purpose subagent, no skill. Prompt: "사용자가 블로그 글을 직접 쓰려 한다. 글을 쓰지 말고 재료를 조사하라. 대상 giftify-be act 도입, 커밋 c1e85af1..6d12e04c. 형식은 네가 판단." 17 tool uses, 125k tokens.

## What it did well

- Detected range overreach (105 commits on develop) and path-filtered to 4
- Quoted diffs and script logic accurately
- Found same patch-id under three hashes
- Looked at the current version of the script for later evolution

## Failures (verbatim where possible)

1. No five-axis structure. Delivered a timeline plus a section titled "글감으로 뽑을 만한 포인트".
2. Framed the story: "'뼈대 먼저, 실행은 나중' 패턴", "좋은 회고 소재", "서사". These are phrasings the author would be tempted to reuse.
3. Inference presented as fact: "Node 20+ 요구사항 대응으로 보임", "같은 세션에 … 발견된 버그로 보임", "시행착오 흔적이 남아있음". No labels anywhere.
4. Section "기각한 대안": absent, and the absence was not reported.
5. Section "결과와 성과": no numbers. Did not run `gh run list`; CI duration, failure count, test count all missing.
6. No questions for the author. The gaps (why skeleton, who decided, how the failure felt) were silently filled with inference.
7. No publication gate or approval check. Not needed for giftify, but the pack did not say so.
8. Did not search the vault or the published Tistory post, both of which exist for this exact subject.
9. Output to chat, no file.
10. Unverified claim: "gradle-build-module composite action은 더 이상 레포에 존재하지 않음" (not checked by a second reader).

## Form chosen for the skill

Shape failure, not discipline failure: the agent complied with "do not write the article" but produced the wrong shape. Per writing-skills "Match the Form to the Failure", the skill states what the output IS (contract + template), with a short never-list for the framing items in failures 2 and 6.

# Production run, 2026-09-19 ~ 20: 18 packs from one repo folder

Input: a whole project folder (1,939 commits, 767 by the user, 6 authors). Scope step produced 18 subjects; the user picked all. 18 extraction agents, each spawning 2 competing fact-checkers. Output 2,137 lines across 18 vault notes, 18 Jira tasks. One rate-limit interruption; 6 packs retried the next day.

## What the contract caught that a plain research prompt would not

- Attribution: three subjects the user named turned out to be substantially another author's work (browser direct upload, registration/edit UI, publishing wiring). Packs carried the split instead of claiming it.
- Eight contradictions between existing manuscripts and the repo, including one in an article already marked ready-to-publish (a first-person decision whose implementing commit belongs to a colleague).
- Two hand-counted numbers corrected by rerunnable scripts.
- One working-tree trap: an agent read repo files from a non-main checkout and described main wrongly; both checkers caught it.

## Rule violations across 18 packs (all fixed by the lead)

| Rule | Packs | Form of the violation |
|---|---|---|
| Section 7 question shape | 01, 02, 06, 07, 13(none), 14, 18 | alternatives, trailing explanation, framing question, future-plan question |
| Working tree vs `git show main:` | 11 | Read tool on a non-main checkout |

The question-shape rule failed in roughly a quarter of packs even after two brief-level patches. Fixed in the skill by replacing the prohibition with four allowed sentence shapes (Match the Form to the Failure: a shaping failure needs a recipe, not a ban).
