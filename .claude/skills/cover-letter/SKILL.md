# Cover Letter Skill

신입 공채 자기소개서를 4명의 전문가 피드백 루프 + `humanize-korean` 윤문으로 작성하는 스킬.

AI 티 제거는 두 단계로 나뉜다. **생성 단계**에서는 `references/anti-ai-detection.md`로
구체성·감정 진폭을 주입하고(내용을 더하는 일 — humanize가 원리상 못 하는 영역),
**검증 단계**에서는 `humanize-korean`이 문체·리듬·번역투를 판정하고 윤문한다(내용을 건드리지 않는 영역).

## 인수 (Arguments)

| 형식 | 설명 | 예시 |
|------|------|------|
| URL | 공고 페이지에서 질문 항목 자동 추출 | `/cover-letter https://recruit.example.com/job/123` |
| 회사명 직군명 | 수동 입력 모드 | `/cover-letter 삼성전자 백엔드개발` |
| 없음 | 대화형 모드로 진입 | `/cover-letter` |

## 실행 절차

### Phase 1: 초기화

#### 1-1. 인수 파싱
- URL이면: WebFetch로 공고 페이지를 가져와 자소서 질문 항목, 글자 수 제한, 마감일, 회사명, 직군명 추출
- 회사명+직군명이면: 사용자에게 질문 항목과 글자 수 제한, 마감일을 대화로 수집
- 없으면: 대화형으로 하나씩 수집

#### 1-2. 프로필 문서 로드 (폴백 체인)
1. `{vault}/02-Areas/career/profile.md` 존재 확인 --> 있으면 Read로 로드
2. 프로필 없으면 --> 사용자에게 알리고 대화로 프로필 생성 제안:
   ```
   프로필 문서가 아직 없습니다. 지금 기본 프로필을 만들까요?
   (학력, 전공, 프로젝트, 기술스택, 경험, 강점/약점 등을 대화로 수집하여 profile.md 생성)
   ```
3. 프로필 생성을 거부하면 --> 기존 자소서 검색 (`{vault}/02-Areas/career/self-intro/자기소개서/` 하위 .md 파일들)

#### 1-3. 문체 학습
기존 자소서나 개인 글이 있으면 분석하여 문체 특징 추출:
- 종결어미 패턴 (습니다/했다/했습니다 비율)
- 평균 문장 길이
- 선호 접속사/연결어
- 감정 표현 방식

문체 분석 결과를 내부 컨텍스트에 저장하여 작성 시 반영.

### Phase 2: 직무분석 문서 생성

자소서 작성 전에 공고 내용을 기반으로 직무분석 문서를 생성하여 별도 파일로 저장한다.

#### 2-1. 직무분석 수행
공고 정보(URL 또는 수동 입력)를 기반으로 다음 항목을 분석:
- 공고 정보 (회사, 채용명, 직군, 마감, 전형 절차, 근무지)
- 지원 자격 (학위, 학점, 어학, 전공, 병역)
- 직무 상세 (주요 업무 내용)
- 우대사항 (기술 스택, 도메인 경험)
- 프로필 매칭 (프로필 문서와 대조하여 강점/리스크 분석)
- TODO (후속 작업 체크리스트)

#### 2-2. 직무분석 문서 저장

출력 경로: `{vault}/02-Areas/career/self-intro/직무분석/{공고마감일}-{회사명}-{직군명}-직무분석.md`

#### 2-3. 사용자 확인
직무분석 문서를 사용자에게 보여주고 확인 후 자소서 작성으로 진행.

### Phase 3: 항목별 초안 작성 (병렬)

자소서 질문 항목이 N개이면, **최대 3개씩 병렬**로 서브 에이전트에게 초안 작성 위임.

각 서브 에이전트에 전달할 컨텍스트:
- 해당 질문 항목 + 글자 수 제한
- 프로필 문서 내용 (해당 질문에 관련된 부분 발췌)
- 회사/직군 정보
- 문체 분석 결과
- AI 탐지 회피 가이드 (`references/anti-ai-detection.md`)

서브 에이전트 핵심 지시:
1. `references/anti-ai-detection.md`를 반드시 Read하여 AI 탐지 회피 규칙 숙지
2. 사용자 문체 패턴에 맞춰 작성
3. 프로필 문서의 팩트만 사용 (날조 금지)
4. 구체적 경험이 부족하면 `[TODO: 본인 경험으로 대체 - 예: XX 프로젝트에서 겪은 구체적 에피소드]` 마커 삽입
5. 글자 수 제한 준수 (+-10% 허용, 기본 500~800자)
6. 자소서 본문은 plain text (마크다운 서식 없음)

---

### Phase 4: 4명 전문가 피드백 루프

초안 완성 후, 4명의 전문가가 동시에 평가. 모든 항목이 100점이 될 때까지 반복.

AI 티 판정은 이 루프에 넣지 않는다. `humanize-korean`은 서브에이전트가 아니라
자체 오케스트레이터 스킬이라 병렬 평가 슬롯에 들어갈 수 없고, 문체 교정은
내용이 확정된 뒤에 해야 재작업이 생기지 않는다. --> Phase 5에서 별도로 수행.

#### 전문가 구성

| 전문가 | 평가 항목 | 기준 |
|--------|----------|------|
| **팩트체커** | 팩트 정확성 | 프로필 문서와 대조. 없는 경험 날조 여부, 수치 정확성 |
| **인사담당자** | 적절성/설득력 | 해당 회사/직군에 맞는 내용인가, 질문 의도에 부합하는가 |
| **문체 전문가** | 자연스러움 | 사용자 문체와 일치하는가, 자연스러운 한국어인가 |
| **구조 전문가** | 구성/흐름/글자수 | 논리적 흐름, 두괄식/미괄식 적절성, 글자 수 준수 |

#### 피드백 루프 절차

```
LOOP (max 5회):
  1. 4명 전문가 동시 평가 (병렬 에이전트, sonnet 모델)
     - 각 전문가가 항목별로 100점 만점 채점 + 구체적 수정 지시 반환
  2. 모든 항목 모든 전문가 100점이면 --> BREAK
  3. 100점 미만 항목이 있으면:
     a. 수정 지시를 반영하여 해당 부분만 재작성
     b. 사용자 입력이 필요한 경우 (팩트 부족, 경험 부재 등):
        --> 사용자에게 질문 + 선택지 제시
        --> 사용자가 스킵(Enter)하면 [TODO] 마커 유지
     c. 다음 라운드로
  4. 5회 초과 시 현재 상태로 확정 + 미달 항목 WARNING 표시
```

사용자 입력 요청 형식:
```
[Round 2/5] 팩트체커 피드백: 92/100
- 3번째 단락 "다양한 경험을 통해 성장했습니다" --> 프로필에 근거 없는 서술

수정 제안: 구체적 경험 한 가지로 대체 필요.
--> 대학/프로젝트에서 겪은 구체적 에피소드가 있다면 알려주세요.
--> 없으면 Enter를 누르면 [TODO] 마커로 대체합니다.
```

### Phase 5: humanize-korean 윤문 (AI 티 제거)

Phase 4에서 내용이 확정된 뒤 실행한다. 항목별 본문을 하나의 입력으로 묶어
`humanize-korean:humanize-korean` 스킬을 호출한다.

#### 5-1. 사전 조건

- **cwd**: `{vault}/02-Areas/career/self-intro/` 로 이동한 뒤 호출한다.
  humanize는 cwd에 `_workspace/{YYYY-MM-DD-NNN}/` 작업 디렉터리를 만든다.
- **입력**: 자소서 본문만. 프론트매터·질문 문구·`[TODO]` 마커 줄은 제외한다
  (마커는 윤문 대상이 아니며 humanize가 문장으로 오인해 다듬을 수 있다).
- **route_hint**: 항목 합계 5,000자 이하면 `standard`, 초과하거나 등급 재도전이면 `heavy`.

#### 5-2. 판정과 재실행

humanize는 `final.md` + `00_metrics.json`을 내고 A~D 등급을 매긴다.

```
1. humanize-korean 호출 --> final.md, 등급 반환
2. 등급 A --> 통과. 5-3으로
3. 등급 B 이하 --> heavy 모드로 1회 재실행
4. 재실행 후에도 A가 아니면 --> 현재 결과 채택 + 등급 WARNING 표시
   (무한 반복 금지. humanize는 내용을 못 바꾸므로 반복해도 수렴하지 않는 경우가 있다)
```

#### 5-3. 팩트체커 재검증 (필수)

윤문은 문체만 바꾼다는 전제이지만, 실제로 의미가 드리프트할 수 있다.
`final.md`를 팩트체커 에이전트에게 다시 넘겨 원본 대비 다음을 확인한다.

- 없던 주장이 생기지 않았는가
- 수치·기간·고유명사가 그대로인가
- `[TODO]` 마커가 보존되었는가
- 글자 수 제한을 여전히 지키는가

하나라도 어긋나면 **해당 문장만** 윤문 전 원문으로 되돌린다. 전체 롤백은 하지 않는다.

## 에러 처리

- 공고 URL 접근 불가 --> "URL 접근 실패. 질문 항목을 직접 입력해주세요."
- 프로필 문서 없음 --> 프로필 생성 대화 시작 또는 기존 자소서 폴백
- 글자 수 초과 --> 자동 축약 후 축약 내용 안내
- 피드백 루프 5회 초과 --> 현재 상태로 확정 + 미달 항목 WARNING
- 문체 참고 글 없음 --> 일반 20대 취준생 톤 + [TODO] 마커 증가
- humanize-korean 스킬 없음/호출 실패 --> Phase 5 스킵. 완료 메시지에
  "humanize 미실행 (AI 티 검증 없음)" 명시. 나머지 Phase는 정상 진행
- humanize 재실행 후에도 등급 B 이하 --> 현재 결과 채택 + 등급 WARNING
