# Book Study Notes

## Overview

책의 **단원 하나**를 개인 볼트의 노트 묶음으로 변환한다.

핵심 원칙: **노트는 원문에서 확인한 것과 다른 근거로 메운 것을 구분해 적는다.**
구분할 수 없으면 그 노트를 만들지 않는다. 볼트는 몇 달 뒤 1차 출처로 재사용되므로,
검증되지 않은 문장이 출처 표시를 달고 들어가면 그때는 걸러낼 방법이 없다.

## When to Use

- 책 단원(장 - 절 - 하위 항목) 단위로 볼트에 노트를 남길 때
- 필사·번역·실습·블로그 초안 등 여러 형태로 같은 단원을 가공할 때
- 예제 저장소가 딸린 기술서적을 실습까지 포함해 정리할 때

사용하지 않는 경우: 아티클·영상 정리(별도 스킬), 책 전체 요약(단원 단위로 쪼갠 뒤 쓸 것).

## 입력

**필수** — 책 제목 / 단원 경로(`책 - 장 - 절 - {하위 항목…}`) / 대상 볼트
**선택** — 원문(PDF·이미지 경로 또는 붙여넣은 본문) / 예제 저장소 URL / 원서 URL / 추가 노트 유형

단원 경로만 주어져도 **작업을 시작한다.** 부족한 입력은 아래 규칙으로 처리하며,
전체를 멈추고 되묻지 않는다.

## 노트 유형

기본 산출은 **학습 + 요점 정리** 2종. 나머지는 명시 요청 시에만 만든다.

| 유형 | 기본 | 원문 없이 가능? | 원문이 없을 때의 동작 |
|---|---|---|---|
| 학습 | ✅ | 조건부 | 공개 1차 출처로 쓰고 `source_note`에 명시 |
| 요점 정리 | ✅ | 조건부 | 위와 동일 |
| 실습 | 선택 | 가능 | 코드를 써서 **직접 실행한다**. 원문 유무와 무관하다 |
| 블로그 초안 | 선택 | 가능 | 본인 실습 결과·경험 기반으로만 |
| 필사 | 선택 | **불가** | 빈 스캐폴드만 생성 — 본문은 사용자가 채운다 |
| 원문 번역 | 선택 | **불가** | 생성하지 않는다 |

## 출처 계약 (모든 노트 필수)

모든 노트의 frontmatter는 `source_note`를 갖는다. 그 값은 세 부분으로 구성된다:

1. **원문에서 직접 확인한 것** — 확인한 적 없으면 `없음`이라고 적는다
2. **다른 근거로 메운 것과 그 근거의 식별자** — 저장소 커밋 해시, 공식 문서 URL,
   런타임 버전처럼 나중에 재확인 가능한 형태로
3. **확인하지 못한 채 남긴 것**

예:

```yaml
source_note: "본문 미제공 — 책에서 직접 확인한 내용 없음.
  아래 API 동작은 JDK 21 java.util.stream 공식 문서와 역서 예제 코드
  (hanbit.co.kr/src/10202, 5장)로 확인함. 책의 서술 순서·강조점은 미확인"
```

## 원문이 없을 때

판정 기준: **사용자가 PDF·이미지 경로를 줬거나 본문을 붙여넣었는가?**

없다면:

- **학습·요점 노트** — 공개된 1차 출처(언어 명세, API 문서, 예제 저장소의 실제 코드)로
  쓴다. 주제를 설명하되, 책이 그것을 어떻게 서술했는지는 쓰지 않는다
- **필사 노트** — 제목·frontmatter·빈 인용 슬롯까지만 만든다
- **원문 번역 노트** — 만들지 않는다
- **어느 경우에도 작업 전체를 중단하지 않는다.** 만들 수 있는 노트를 만들고,
  생략한 것과 그 이유를 마지막에 한 줄씩 보고한다

## 서지 정보는 받은 것만 적는다

장·절 번호, 저자명, 역자명, 판본, 원서 제목, 페이지, 절 제목은 **사용자 입력이나
제공된 원문에 있을 때만** 적는다. 기억으로 채우지 않는다.

모를 때의 처리:

- frontmatter의 해당 **줄을 통째로 뺀다.** `"미상"`이나 추측값을 넣지 않는다
- 장 번호를 모르면 폴더를 `{주제 슬러그}/`로 두고 파일명은 `{주제}_{유형}.md`로 한다
- MOC 진도 표의 장 칸은 `?`로 둔다
- 마지막 보고에 한 줄 적는다 — "장 번호를 몰라 `{...}`로 두었다. 알려주면 정정한다"

빈 필드는 나중에 채울 수 있지만, 그럴듯한 값이 들어간 필드는 아무도 다시 확인하지 않는다.

## 실습 노트는 실행이 전제다

실습 노트를 만들기로 했으면 **코드를 작성하고 실제로 실행한다.** 원문이 없어도 실습은
가능하다 — 검증 대상은 책의 문장이 아니라 언어·런타임의 실제 동작이기 때문이다.

1. `{NN}장/src/`에 실행 가능한 코드를 쓴다
2. 실행하고 **출력을 그대로 붙여넣는다**
3. `src/RUN.md`에 명령과 검증 환경(런타임 버전 실측값)을 적는다

런타임이 없어 실행할 수 없을 때만 스캐폴드로 남기고, **왜 실행하지 못했는지를
`source_note`에 적는다.** "사용자가 나중에 채울 것"은 이유가 아니다.

## 금지 — 없는 원문을 있는 것처럼 쓰지 않는다

- 책 본문을 기억으로 재구성해 인용 부호(`>`)에 넣지 않는다
- 원서를 읽지 않은 채 `English (Original)` 류의 라벨을 붙여 영문을 만들지 않는다
- 실행하지 않은 코드의 출력을 실습 결과로 적지 않는다
- 사용자 입력·제공된 원문·재확인 가능한 출처 중 **어디에도 없는 값**을 적지 않는다.
  위 목록은 예시일 뿐 한계가 아니다 — 목록에 없다는 것이 허용의 근거가 되지 않는다

**예외 없음:**

- 유명한 책이어도 예외가 아니다
- 내용이 사실상 맞아도 예외가 아니다 — 맞는 것과 그 책이 그렇게 썼다는 것은 다른 주장이다
- 사용자가 이미 그 책을 갖고 있어도 예외가 아니다 — 대조하는 건 내가 아니다

## Red Flags — 여기서 멈춘다

- "이 책 내용은 대충 아니까 인용을 복원할 수 있다"
- "번역 노트니까 영문은 그럴듯하게 만들어두면 된다"
- "실습 노트에 예상 출력을 적어두면 나중에 확인하겠지"
- "람다는 3장인 거 다들 아는데 장 번호쯤은 채워도 된다"
- "실습 노트는 빈 칸으로 두면 사용자가 알아서 채우겠지"
- "원문이 없으니 아무것도 못 만든다. 물어봐야 한다"
- "고지는 사용자한테 말로 하면 되고 노트에는 안 적어도 된다"

앞의 세 개는 **위조**, 네 번째는 **서지 위조**, 다섯 번째는 **실행 회피**,
여섯 번째는 **차단 과잉**, 일곱 번째는 **출처 계약 위반**이다.
전부 규칙 위반이며, 해당 노트를 지우고 이 문서의 규칙대로 다시 만든다.

## 합리화 대응표

| 변명 | 실제 |
|---|---|
| "인용이 거의 정확할 것이다" | 거의 정확한 인용은 인용이 아니라 위조다 |
| "따옴표를 안 쓰면 인용이 아니다" | 출처가 적힌 노트 안의 서술은 전부 그 출처에 귀속된다 |
| "고지를 달면 노트가 지저분해진다" | `source_note`는 frontmatter다. 본문은 깨끗하다 |
| "원문 없이 만들면 가치가 없다" | 1차 출처 기반 학습 노트는 그 자체로 유효하다. 책 인용만 못 할 뿐 |
| "일단 물어보는 게 안전하다" | 만들 수 있는 노트를 안 만드는 것도 실패다. 만들고 생략분을 보고한다 |
| "실습 노트는 과제 목록이면 된다" | 실습 노트는 실행한 결과다. 과제 목록은 학습 노트에 속한다 |
| "장 번호는 널리 알려진 사실이다" | 널리 알려진 것과 이 판본이 그렇다는 것은 다른 주장이다. 판본은 갈린다 |
| "빈 필드를 두면 노트가 불완전해 보인다" | 빈 필드는 나중에 채워진다. 채워진 추측값은 영원히 재확인되지 않는다 |
| "실습은 사용자가 직접 해야 의미가 있다" | 사용자는 결과를 보고 배운다. 실행은 내 몫이고 스캐폴드는 도피다 |

## 파일 배치

```
{볼트}/{책 슬러그}/
  {책 이름} MOC.md
  {NN}장/
    {NN}-{MM}_{주제}_{유형}.md
    src/                     ← 실습 노트를 만들 때만
      RUN.md                 ← 실행 명령과 검증 환경
```

- `{유형}` = `학습` / `요점` / `필사` / `번역` / `실습` / `초안`
- 한 파일에 두 유형을 섞지 않는다
- 파일명을 flat하게 두지 않는다 — 장 폴더는 필수다

## MOC 갱신 (필수)

단원 노트를 만들 때마다 책 MOC의 해당 행을 갱신한다. MOC이 없으면 **먼저 만든다.**
MOC에는 진도 표(장·주제·노트 링크·상태)와, 역서/원서 판본이 어긋나면 그 대응 관계를 적는다.

## 볼트 어댑터

| 볼트 | 쓰기 방법 | 주의 |
|---|---|---|
| ZenNotes | `mcp__zennotes__create_note` | 반환된 `path`를 그대로 재사용. `inbox/` 접두사를 붙이지 않는다 |
| Obsidian | `{OBSIDIAN_VAULT}/03-Resources/` 아래 직접 파일 쓰기 | PARA 구조를 지킨다 |

볼트가 지정되지 않으면 사용자에게 묻되, **그 질문 때문에 노트 작성을 멈추지 않는다** —
스크래치패드에 먼저 쓰고 볼트 확정 후 옮긴다.

## 노트 템플릿

각 유형의 frontmatter와 본문 뼈대는 `references/note-templates.md` 참조.

## Common Mistakes

- **전면 차단** — 원문이 없다고 산출물 0개로 끝내기
- **위조 인용** — 기억으로 복원한 문장에 `>` 붙이기
- **`source_note` 누락** — 나중에 무엇이 검증됐는지 알 수 없게 됨
- **flat 파일명** — 장 폴더 없이 볼트 루트에 쏟아붓기
- **MOC 미갱신** — 노트는 늘었는데 진입점이 그대로
- **실습 노트에 미실행 결과** — 예상 출력을 실측처럼 적기
