# 노트 템플릿

`{중괄호}`는 채울 자리다. frontmatter 필드는 임의로 빼지 않는다 —
특히 `source_note`는 모든 유형에서 필수다.

## 공통 frontmatter

```yaml
---
title: {노트 제목}
book: {역서 제목}
book_original: {원서 제목 (판)}      # ↓ 아래 4개는 사용자가 준 값이 없으면 줄을 통째로 뺀다
author: {저자}                        #    기억으로 채우지 않는다. "미상"도 쓰지 않는다
chapter: "{NN}"                       #    장 번호를 모르면 파일명·폴더도 주제 슬러그로 간다
section: "{절 범위 또는 '{N}장 전체'}"
note_type: {학습|요점|필사|번역|실습|초안}
lang: ko
tags:
  - book/{책 슬러그}
  - note/{유형}
  - {도메인 태그 0~3개}
source_repo: {예제 저장소 URL}        # 없으면 줄을 뺀다
source_note: "{원문 확인분 / 다른 근거로 메운 분 + 식별자 / 미확인분}"
created: {YYYY-MM-DD}
status: seedling
related:
  - "[[{같은 단원의 다른 노트}]]"
---
```

`status`는 `seedling` → `growing` → `evergreen` 순으로 사용자가 직접 올린다.
생성 시점에는 항상 `seedling`이다.

## 학습 노트

단원을 처음부터 이해하기 위한 노트. 가장 긴 형태다.

```markdown
# {N}장 {단원 제목}

> 한 줄 요약: {이 단원이 결국 무엇을 주장하는가}

## 이 단원이 답하는 질문

- {질문 1}
- {질문 2}

## 절 구성

| 절 | 내용 |
|---|---|
| {절 이름} | {한 줄} |

## {하위 항목 1}

{설명. 코드 예제는 실제로 컴파일·실행 가능한 형태로.}

## 헷갈리는 지점

{읽으면서 막히는 부분과 그 해소}

## Related

- [[{연결 노트}]]
```

원문이 없을 때: `## 절 구성` 표는 **사용자가 준 하위 항목 목록만** 채운다.
책의 절 제목을 추측해 채우지 않는다.

---

## 요점 정리 노트

복습용 압축 노트. 학습 노트를 읽지 않고도 핵심이 복원돼야 한다.

```markdown
# {단원 제목} 요점

## 한 문장

{단원 전체를 한 문장으로}

## 핵심 3~7개

1. **{개념}** — {한두 줄}

## 코드로 보는 차이

```{lang}
// 이전
{코드}
// 이후
{코드}
```

## 자주 틀리는 것

| 오해 | 실제 |
|---|---|

## Related
```

## 필사 노트

**본문은 사용자가 채운다.** 원문이 없으면 아래 뼈대까지만 만들고 멈춘다.

```markdown
# {단원 제목} 필사

> 이 노트의 인용은 사용자가 직접 옮겨 적는다. 비어 있는 슬롯을 채워 완성한다.

## {하위 항목 1}

> (원문)

**내 말로 바꾸면**

{빈칸}

**질문**

{빈칸}
```

원문이 제공된 경우에만 `> (원문)` 자리를 채운다. 그때도 제공된 텍스트 범위를
벗어나 확장하지 않는다.

---

## 원문 번역 노트

**원서 텍스트가 실제로 제공된 경우에만 만든다.** 아니면 만들지 않는다.

```markdown
# {단원 제목} 원문 대조

## {소절}

**Original**
> {제공된 원서 텍스트 그대로}

**옮김**
> {번역}

**용어**
| EN | KO | 메모 |
|---|---|---|
```

역서 번역문과 비교할 때는 역서 문장 역시 제공된 것만 인용한다.

## 실습 노트

**코드를 써서 실제로 실행한 뒤 작성한다.** 빈 표를 남기고 사용자에게 넘기지 않는다.
런타임이 없어 실행하지 못한 경우에만 스캐폴드로 두고, 그 이유를 `source_note`에 적는다.

```markdown
# {단원} 실습 — {무엇을 확인하려는가}

## 이 실습이 확인하려는 것

1. {검증 명제 — 참/거짓이 판별 가능한 형태로}

## 환경

- 런타임: {정확한 버전}
- 예제 저장소: {URL} — {브랜치}, 커밋 `{해시}`
- 빌드 설정 실측: {실제로 읽은 값}

## 실행

{명령과 그 출력. 출력은 붙여넣은 실제 결과다.}

## 결과

| 검증 명제 | 결과 | 근거 |
|---|---|---|

## 배운 것
```

코드는 `{NN}장/src/` 아래 두고 `src/RUN.md`에 실행 명령과 검증 환경을 적는다.

## 블로그 초안 노트

발행용이 아니라 **초안**이다. 본인 실습 결과와 경험만으로 쓴다.

```markdown
# (초안) {제목 후보}

> 상태: 초안. 발행 전 팩트체크 필요.

## 왜 이 글인가

{내가 막혔던 지점}

## 검토한 대안과 기각 사유

| 대안 | 기각 사유 |
|---|---|

## 측정

{실습 노트에서 가져온 수치}

## 남은 확인 사항

- [ ] {팩트체크 항목}
```

책 내용 요약을 그대로 옮긴 초안은 만들지 않는다 — 발행 시 저작권 문제가 되고,
포트폴리오 가치도 없다.
