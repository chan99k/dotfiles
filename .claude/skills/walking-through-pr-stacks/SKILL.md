# Walking Through PR Stacks

## Overview

스택된 PR 여러 건의 동작을 종합해 설명한다.

핵심 원칙: **PR 본문이 자기 설계를 어떻게 부르는지는 근거가 아니다.** 흐름 설명은 무지시로도
나온다. 빠지는 것은 그 설계가 무엇을 대가로 치르는지, 무엇에 조용히 의존하는지다.

## When to Use

- 열린 PR 여러 건이 서로를 base로 쌓여 있고, 합쳐진 동작을 알고 싶을 때
- 기능 하나가 여러 PR에 걸쳐 구현되어 한 PR만 봐서는 흐름이 안 보일 때

쓰지 않는 경우:
- 단일 브랜치의 변경 내역 설명 -> `brief-me`
- 내 변경이 어디에 닿는지 사전 분석 -> `inspect`

## 수집

1. `gh pr list --json number,baseRefName,headRefName` 으로 의존 순서를 확정한다.
   추측하지 않는다. base 체인이 순서다.
2. PR별로 `gh pr diff <번호> --name-only` 를 받아 **변경 파일 경로 목록**을 확보한다.
   경계 침범 슬롯은 이 목록에서만 판정한다.
3. 바닥 PR부터 읽는다: 마이그레이션 SQL, 도메인 모델, VO **원문**.
4. 위 PR을 읽는다: 유스케이스 오케스트레이션 **원문**.
5. 술어(JPQL WHERE, 정렬 비교자)와 계산 루프는 반드시 원문을 본다.
   diff 요약이나 PR 본문 서술로 대체하지 않는다.
6. 술어가 필터를 조인에 의존하면 **조인 대상 엔티티 클래스도 연다.**
   필터가 JPQL에 없으면 엔티티 어노테이션에 있다.

## 출력 계약

흐름 설명(데이터 모델 / 쓰기 / 읽기 / 계층)에 이어 **`## 구조적 관찰` 절이 온다.**
아래 네 슬롯을 모두 채운다. 해당 없으면 그 슬롯에 `없음`이라고 쓴다 - 슬롯을 지우지 않는다.

**모든 항목은 `파일:줄` 앵커로 시작한다.** 앵커를 붙일 수 없으면 그 항목을 쓰지 않는다.
확인이 필요한데 못 읽었으면 `미확인:` 으로 시작하는 한 줄을 남긴다 - 추정을 서술로 쓰지 않는다.

- **대가**: 이 설계 형태가 매 요청에 부과하는 비용. 간접층 하나당 조인 몇 개, 왕복 몇 회인가.
- **숨은 의존**: 코드가 조용히 기대하는 것. 결과에 쓰이지 않는 조인, 문자열 리터럴 안의
  컬럼명, 어노테이션에만 존재하는 조건. "이 줄을 지우면 무엇이 깨지나"로 찾는다.
  필터를 서술하려면 **그 필터가 적은 파일:줄**을 앵커로 쓴다. 쿼리에 없으면 엔티티에 있다.
- **규모 가정**: 전량 로딩(`findAll`), 메모리 그룹핑, N+1. 몇 건까지 버티는 설계인가.
- **경계 침범**: 판단이 아니라 목록 대조다. 두 단계로만 쓴다.
  1. 수집 2단계의 변경 파일 목록에서, 이 스택의 주 패키지(예: `review`) **밖**에 있는
     경로를 그대로 옮겨 적는다. 밖 경로가 없으면 `없음`.
  2. 옮겨 적은 경로가 있으면 그것이 정당한지 한 줄로 판단한다.

  런타임에 다른 컨텍스트를 **참조**하는 것은 이 슬롯이 아니다(그건 정상 의존 방향).
  이 슬롯은 다른 컨텍스트의 파일을 **수정**하는 것만 본다.

메서드명, 시그니처, 술어는 앵커가 가리키는 원문에서 그대로 옮긴다.
인용 블록은 **복사**다 - 줄을 빼거나 다른 파일의 이름을 섞으면 인용이 아니다.
JPQL은 엔티티 필드명(`startDate`)을, 마이그레이션은 컬럼명(`planned_start_on`)을 쓴다.
둘이 다르면 섞지 말고 나란히 적는다.
헤지(`~인 것으로 보이며`)는 지어낸 것과 같게 취급한다 - 앵커가 없으면 헤지도 쓰지 않는다.
diff가 잘렸으면 파일을 직접 Read 한다. 잘린 채 서술하지 않는다.

### Red Flags - 멈추고 원문을 열어라

- `## 구조적 관찰`의 항목에 `파일:줄` 앵커가 없다
- 필터·술어를 서술하는데 그것이 적힌 파일을 열지 않았다
- 경계 침범 슬롯에 파일 경로가 아니라 판단만 적혀 있다
- `## 구조적 관찰`의 슬롯이 비어 있거나 지워졌다
- 설계 결정을 나열했는데 전부 장점이다

## Common Mistakes

**이득만 나열** - "핵심 설계 결정" 목록이 전부 장점이면 대가를 안 찾은 것이다.
모든 간접층에는 값이 붙는다.

**스택 순서를 PR 번호로 추측** - 번호순과 의존순은 다르다. `baseRefName`을 본다.

**설명을 PR별로 쪼갬** - 독자가 알고 싶은 것은 합쳐진 동작이다. PR 경계가 아니라
흐름(쓰기/읽기)을 축으로 묶는다. 어느 PR이 무엇을 놓았는지는 계층 지도 한 장으로 족하다.
